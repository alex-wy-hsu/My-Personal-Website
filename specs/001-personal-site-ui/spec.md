# 規格說明：打造個人網站 - 視覺與滑鼠互動實作

**Feature Branch**: `001-personal-site-ui`  
**Created**: 2026-01-21  
**Status**: Draft

## Clarifications

### Session 2026-01-21

- Q: Which image comparison metric should be used for automated screenshot diffs? → A: Use SSIM (Structural Similarity Index) as the primary comparison metric for perceptual similarity; start with a threshold of 0.98 and adjust with design review.

## 使用情境與測試 (必要)

### 使用情境 P1 — 首頁視覺與滑鼠互動（最優先）
作為一名網站訪客，我想在首頁看到與 `figma-site-snapshots` 中截圖一致的版面與滑鼠懸停效果，讓我能直觀感受網站風格。

**驗證方式**：人工或自動化比對開發產出截圖與 `figma-site-snapshots` 中的基準圖，並確認懸停效果在滑鼠移至指定元件時呈現。

**接受條件**：
1. 畫面佈局（頁首、導覽、英雄區、專案卡片、部落格列表）與基準圖在主要元素位置與比例上相符。
2. 指定互動（例如專案卡片、terminal 區塊）在滑鼠懸停或鍵盤 focus 時產生相同的視覺變化（顏色、陰影、邊框或圖層變化）。

---

### 使用情境 P2 — Projects 頁面專案懸停（次要）
作為訪客，我在 Projects 頁面將滑鼠移至「Project Alpha」時，該專案卡片應顯示明顯的懸停效果（如放大、浮起或顯示按鈕）。

**驗證方式**：在 Projects 頁面，對 `Project Alpha` 執行滑鼠移入，觀察畫面是否呈現與基準圖一致的狀態。可用自動化腳本將滑鼠移至元素並截圖比對。

**接受條件**：在桌面瀏覽器/Chrome 相容環境，滑鼠移入 1 秒內出現預期視覺變化；鍵盤 focus 同等效果（可用 Tab 觸發）。

---

### 使用情境 P3 — 可及性與行動裝置表現（P3）
使用鍵盤導航或行動裝置時，互動應以可及性為優先，滑鼠懸停的視覺補償（例如 focus 狀態）需等效於懸停效果。

**驗證方式**：使用鍵盤 Tab 鍵巡覽或在手機尺寸下模擬觸控/長按，確認互動狀態可被觸發且畫面仍可辨識。

---

### 邊界情況
- 無滑鼠（僅鍵盤）或行動裝置：必須提供 focus/觸控替代狀態。
- 動態載入（lazy load）導致元素尚未渲染：需在載入完成後可觸發懸停測試。

## 功能需求 (可測試、必要)

### 主要功能
- **FR-001**：實作首頁、Projects 與 Blog 列表頁面，畫面佈局應參照 `figma-site-snapshots` 的截圖（像素位置不必 100% 相同，但主要元素位置與層次應一致）。
- **FR-002**：專案卡片（Project Card）必須包含：標題、縮圖、簡短描述、tag 與可點擊連結。
- **FR-003**：當滑鼠懸停在專案卡片（例：Project Alpha）上時，卡片必須顯示懸停視覺效果（例如陰影增強、微幅放大、顏色變化或顯示操作按鈕）。
- **FR-004**：首頁中的 `terminal` 區塊（若存在於截圖中）在滑鼠懸停或 focus 時需產生與截圖一致的視覺變化。
- **FR-005**：所有懸停效果應有對應的鍵盤 focus 樣式（可及性），且動畫時長在 0.1s–0.5s 範圍內以維持反應速度。
- **FR-006**：響應式設計：在 320px（手機）至 1366px（桌面）範圍內，排版不會遮蔽重要資訊，並保留可用的互動觸發方式（觸控或 focus）。

### 非功能 / 可驗證條件
- **FR-007**：在主要目標瀏覽器（最新 Chrome、Firefox、Edge）上，懸停/焦點行為必須一致。
- **FR-008**：開發完成後必須能透過自動化截圖工具比對以驗證視覺一致性；首選使用 SSIM（Structural Similarity Index）作為感知相似度指標，初始門檻建議設為 0.98（可由設計驗收時調整）。

## 關鍵資料實體
- **ProjectCard**：{ title, slug, thumbnailUrl, shortDescription, tags, link }
- **SiteSnapshot**（供 QA 用）：{ name, path, createdAt }

## 成功準則 (可衡量)

- **SC-001**：90% 以上的主要視覺元素（標題、卡片位置、主要色塊）與 `figma-site-snapshots` 基準圖在自動化比對中落在容差範圍內（容差由設計/PM 定義）。
- **SC-002**：在桌面瀏覽器中，將滑鼠移至 `Project Alpha` 時 95% 的測試迭代都在 1 秒內呈現預期懸停樣式。
- **SC-003**：Keyboard navigation 能觸發與滑鼠相同的互動／視覺狀態（可及性檢測通過）。
- **SC-004**：在主要瀏覽器與行動視窗大小下，主要頁面在首次載入後 3 秒內可完成互動（不含資源下載延遲）。

## 假設
- `figma-site-snapshots` 中的截圖為視覺與互動的權威基準。
- 所有內容（文字、縮圖）在初期可用靜態替代資料，不需要即時後端內容。
- 開發與測試以現代桌面瀏覽器為主，必要時補上行動裝置的替代互動方式。

## 交付項目
- 前端樣板/樣式（HTML/CSS/JS 或相等技術）以匹配截圖與互動行為。
- 自動化截圖比對腳本與簡易測試步驟記錄。

## 下一步建議
1. 指派設計驗收人員確認容差定義（像素容忍度、互動細節）。
2. 開發小切片：先實作首頁的主要區塊與一個專案卡片（P1），並驗證懸停效果。
3. 之後實作 Projects 頁面與可及性補償。
